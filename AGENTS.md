# Repository Guidelines

## Project Structure & Module Organization
Core application code lives in `tram/`. Key areas are `tram/api/` for FastAPI routers and middleware, `tram/pipeline/` for loading, execution, and lifecycle control, `tram/models/` for Pydantic config schemas, and `tram/connectors/`, `tram/transforms/`, and `tram/serializers/` for plugin implementations. The web UI is in `tram/ui/`. Deployment assets live in `helm/`, `Dockerfile*`, and `docker-compose.yml`. Helper automation lives in `scripts/` (for example `scripts/deploy-kind-tram-dev.sh`). Tests are split into `tests/unit/` and `tests/integration/`, plus the Playwright browser smoke suite under `tests/browser/` (fixture-stubbed API responses against a fresh `tram/ui` build). Example pipeline YAMLs live in `pipelines/`, and user-facing docs are under `docs/`, including roadmap and design notes for upcoming architecture work.

## Build, Test, and Development Commands
- `pip install -e ".[dev,manager]"`: install the app with local editable dependencies and manager-only extras.
- `tram version` / `tram plugins`: verify the CLI and plugin registration.
- `tram validate pipelines/minimal.yaml`: validate a pipeline and run lint rules.
- `tram daemon`: start the API and scheduler locally on `localhost:8765`.
- `pytest tests/unit/ -q`: run fast unit tests.
- `pytest tests/integration/ -q`: run integration coverage for end-to-end behavior.
- `pytest tests/ -q`: run the full backend suite. In Codex/sandboxed agent sessions, always run this outside the sandbox because the sandbox blocks asyncio cross-thread wakeups used by FastAPI `TestClient`.
- `pytest tests/ --cov=tram --cov-report=term-missing`: run the full suite with coverage.
- `ruff check .` and `ruff check --fix .`: lint and auto-fix style issues.
- `./scripts/deploy-kind-tram-dev.sh`: build local images, load them into kind, and upgrade the `tram-dev` Helm release.
- `cd tram/ui && npm run build`: verify the UI build before merging frontend changes.

## Coding Style & Naming Conventions
Use Python 3.13+ with 4-space indentation and type hints on new code. Keep modules and functions `snake_case`, classes `PascalCase`, and tests named `test_*.py`. Follow existing plugin naming patterns such as `@register_source("kafka")`. Prefer small, focused changes and update docs when behavior changes. Ruff is the enforced linter; line length is 100. Do not add AI assistant signatures, "generated by AI" comments, or attribution markers in source code, commits, issues and pull requests.

## Testing Guidelines
Pytest is the test runner. Add unit tests beside the affected area, for example `tests/unit/test_api_pipelines.py` or `tests/unit/test_kafka_connectors.py`. Keep integration tests for cross-module or I/O behavior. In Codex/sandboxed agent sessions, always run full-suite pytest commands (`pytest tests/ -q`, `pytest tests/ --cov=tram --cov-report=term-missing`) outside the sandbox, since the sandbox breaks FastAPI `TestClient` by blocking asyncio wakeup sockets. Run coverage locally before opening a PR and avoid reducing the project coverage gate.

## Commit & Pull Request Guidelines
Recent history follows Conventional Commit style, e.g. `fix(executor): ...` and `docs: ...`. Use that format where possible: `fix(...)`, `feat(...)`, `docs`, `chore`, `test`. PRs should include a short description, impacted modules, test evidence, and any doc or config updates. Include screenshots for `tram/ui/` changes and mention Helm, Docker, or API contract changes explicitly.

## Release Gate (mandatory)
Releases are tag-triggered and gated — merging to main never publishes. Before tagging any version: bump and align the version in `pyproject.toml`, `helm/Chart.yaml` (`version` + `appVersion`), and `tram/ui/package.json`; rename `docs/changelog.md` `[Unreleased]` to the release version; record review sign-off (self-review checklist + independent review of the full diff) in the release PR; then run `scripts/release-gate.sh` and require every check green (11 checks: clean tree, version consistency, tag check, changelog, `ruff check .`, pytest + coverage floor 75%, UI build, UI browser smoke — Playwright over `tests/browser/`, which needs node >= 20 or `TRAM_BROWSER_NODE=/path/to/node20` — example-pipeline validation, Helm lint/template, docs-sync). Tag as `vX.Y.Z` (equal to the pyproject version) to trigger `.github/workflows/release.yml`, which re-runs the gate on the tag before publishing images and the Helm chart. Never tag past a red gate — a maintainer override requires written justification in the release PR. See `docs/release-gate.md` for the full procedure.

## Security & Configuration Tips
Do not commit secrets, tokens, or private keys. Add new environment variables to `.env.example`, document them in `docs/deployment.md`, and update Helm values when applicable. The GitHub release workflow authenticates to GHCR with the built-in `GITHUB_TOKEN` (job-level `permissions: packages: write`); no PAT secret is required.
