| F183-01 / H183-05 / B089 | Original PGW ASN.1 `thread_workers=2` throughput/RSS benchmark | Obtain the matching corpus, schema/root type and original pipeline/transforms; record checksums and record counts. Pin CPU/memory limits, Python/decoder versions, serializer chunk size, worker configuration and allocator settings. Run the matching baseline/current comparison and repeat under the same resources. | F183-02 / H183-01 | Kafka source commit-response loss | Use an isolated broker/proxy to lose the response after a real commit request. | F183-03 / H183-01 | Kafka network-only heartbeat blackout | Interrupt the consumer's network while the broker stays running; exercise session expiry/rebalance with in-flight input. Verify assignment fencing, retained ownership and contiguous decided commits after recovery. Include exact output content, duplicate accounting and restart where recovery is relevant. A stopped broker is separate evidence and does not close this scenario. |
| F183-04 / H183-01 | Successful Kafka producer retry after timeout | Reproduce a real timeout followed by a successful retry. Reconcile every offered input with exact output bytes, acknowledged source records and any ambiguous first publication. Record duplicate windows and distinguish recovery from already-covered retry exhaustion or rejected publication. |
| F183-05 / H183-03 | Actual ClickHouse worker-process restart | Use an isolated worker/executor process and replayable source; restart that process with buffered or failed output obligations. | F183-06 / H183-03 | Physical ClickHouse response loss | Lose a real native-protocol response after server-side insertion using an isolated proxy/network fault. Show exact inserted contents and retained uncertain ownership, then reconcile recovery/replay and duplicates. The controlled error injected after a real insert is existing client-boundary uncertainty evidence; it does not close physical response loss. |
