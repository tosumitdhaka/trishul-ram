## Objective and scope admission

Prove that existing connectors handle dependency failure without silent loss,
premature acknowledgement, destructive file finalization or false success.
This is a targeted Kafka/AMQP/ClickHouse/SNMP/file-finalization pass, not delivery
of every capability in #58–#61. v1.8.0 already addressed several of these paths;
verification can close a concern with evidence without changing implementation.

Before a fix enters scope, record its current failure scenario, affected delivery
tier, expected result, reproducible test and patch-compatible change. If a
connector needs a new protocol, feature or broad redesign, retain the residual
as unscheduled work. The approved exception on 2026-10-12 is H183-07: a bounded
ten-IP SNMP polling pilot for the demo. Split an oversized patch before scope freeze and document
the new assignment; never silently defer a reproduced release-blocking defect.

## Verification method

Use the existing Kafka, AMQP and ClickHouse live-broker suites and SNMP wire
harness as starting points. Keep deterministic failure checks in normal CI;
run the selected real-service profile explicitly for the release. A skipped
live profile is missing evidence, not a pass. Record service versions and
scenario results in a dated `docs/reviews/` report with raw evidence links.

Give source records stable identities. Reconcile offered/admitted inputs,
confirmed output per sink, retained state, filter/drop/DLQ dispositions and
source acknowledgements. Inspect output content and order where contractual.
Report retries and duplicates rather than asserting universal exactly-once.
Classify unreplayable source loss honestly; UDP traps and in-memory webhook
acceptance do not gain a durability guarantee through this release.

Run each selected live fault/recovery scenario at least three times, including
a worker restart where recovery is relevant. Uncertainty must retain ownership
until resolved; a timeout alone cannot authorize replacement execution.
