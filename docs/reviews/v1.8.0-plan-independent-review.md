# v1.8.0 plan — independent review and disposition

Date: 2026-10-08. Baseline: v1.7.0 / `8e128dd`.
Scope: [implementation plan](../plans/v1.8.0-reliability-performance-plan.md)
for all R1–R16 in the [source review](worker-pipeline-reliability-performance-2026-10-08.md),
with assignment in the [roadmap](../roadmap.md).

Two separate reviewers independently read the draft, repository instructions,
source findings, and relevant implementation. Neither authored the plan; neither
changed files or ran tests. Their reviews cover architecture/ownership/recovery
and delivery/deployment/performance respectively. This is design review evidence;
implementation and release sign-off require a later review of the full code diff
and the mandatory release gate.

## Initial verdicts

Both reviewers requested amendments before approval. Both found all R1–R16
assigned to concrete packages and fault scenarios. The architecture reviewer
identified five blocking contracts; the delivery reviewer identified three,
including one overlap. The delivery reviewer judged the dependency waves and
65–99 engineering-day estimate plus contingency credible for this scope.

## Amended-plan verdicts

- **Delivery/deployment/performance reviewer: approve; no unresolved blockers.**
  All blocking and nonblocking recommendations were resolved, with R1–R16,
  sequencing, estimates and evidence coherent. An editorial follow-up corrected
  V18-02's reversed publication oracle to require source finalization only after
  all required publications commit.
- **Architecture reviewer: one remaining amendment on first re-review.** A1–A4
  and all other recommendations were resolved. A5 needed GC itself to advance
  the persisted rejection watermark atomically: validation at 100, expiry 150,
  idle GC at 200 and restart clock 140 could otherwise admit the retired token.
  The plan now includes the exact invariant and fault scenario, plus forward-clock
  recovery that invalidates old authorization epochs before lowering the watermark.
  **Final verdict: approve for implementation; no unresolved architecture
  blockers.** The reviewer verified that admission and GC both advance the
  watermark, deletion is atomic with its update, clock recovery invalidates old
  authorization epochs, and the exact fault scenario is included. A1–A4 and
  the corrected publication oracle remain consistent.

Both independent reviewers approve the amended plan. All requested amendments
and recommendations are incorporated; no plan-review blocker remains. Wave 0
still freezes exact schema/interfaces/defaults and reviews their detailed design.

## Follow-up blind review round

Date: 2026-10-08, after the amended-plan verdicts above. A third reviewer read
the plan, the source findings, repository instructions, and the implementation
without reading this record or any prior review identity — the round was
deliberately blind to preserve independence. Verdict: **approve with
amendments; no blockers.** All R1–R16 characterizations were independently
confirmed against the v1.7.0 code with file-and-line evidence (ClickHouse
buffer cleared before insert succeeds, AMQP ack-before-disposition, the boot
assumption that nothing is in flight, daemon-thread Uvicorn servers taking
default SIGTERM disposition, `db = None` fallback after failed inits,
unbounded source queues, the absent queue `flush` flag, and `emptyDir` worker
state requiring an immutable StatefulSet recreation). Coverage, wave ordering,
and the machine-time budget were judged sound; the effort envelope was judged
optimistic at the top end.

|---|---|---|
| F1 | V18-05's "completion replays with PVC" oracle depends on wave-3 chart infrastructure | Wave-2 validation uses a manually provisioned persistent mount; the storage-dependent replay oracle is re-verified at the wave-3 exit gate |

Recommendations incorporated: the effort envelope widened with a named

for the Wave 0 campaign; plan status claims now attribute approval to this
record by reference.
