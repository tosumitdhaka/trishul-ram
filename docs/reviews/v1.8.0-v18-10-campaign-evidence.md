Broker-gate findings:

1. **Live defect found and fixed** — the AMQP source's generator `finally`
   called `stop_consuming()`/`connection.close()` from the reader thread while
   the consume thread drove the pika ioloop. pika's blocking adapter is not
   thread-safe; shutdown consistently hung >5 s and aborted the transport
   (`StreamLostError`). Fixed in `ddada07`: cancel marshalled via
   `add_callback_threadsafe`, connection closed in the consume thread's own
   `finally`, reader joins it; added the missing `stop()` override (the
   executor's stop-watcher call was previously a no-op — an idle AMQP `read()`
   could not be unblocked). Stress-verified 5/5.
2. **Stopgap removed** — the strict + Kafka + `thread_workers > 1` rejection
   was deleted (`ac584c3`) after the threaded-frontier gate passed live. The
   rejection text is preserved in the commit message; the deployment doc now
   states acceptance with the broker-proven note (`095377d`).
3. Harness notes: the kind Kafka broker is reachable via the EXTERNAL listener
   (`172.19.0.2:30094`); through the NodePort the advertised listener breaks
   new-topic metadata. `kafka-python` 2.x `KafkaAdminClient.check_version` fails
   against the Kafka 3.9 broker — the test helper pins `api_version=(2,5,0)`.

## Durable-contract cells — per-record Kafka commit-barrier cost

Measured (not guessed) against the live kind broker, ~100-byte JSON records,
N=1000/rep, 3 reps, medians (harness: `/tmp/opencode/kafka-barrier-bench/bench.py`,
ephemeral):

| Mode | Median rec/s | Reps |
|---|---|---|
| Pipelined producer (`acks=all`, buffered, one flush) | 7086 | 7037 / 7086 / 7245 |
| Shipped sink, N writes + 1 `commit()` | 1245 | 1276 / 1245 / 1103 |
| Shipped sink, `write()` + `commit()` per record | 1179 | 1181 / 1179 / 1147 |

Interpretation (source-verified, `tram/connectors/kafka/sink.py`):
`_send_chunk` **waits on the ack future per message**, so the durable
confirmation is paid inside `write()` — the v1.8 synchronous-durable design
(per-message fail-loud for the executor's retry/backoff/circuit-breaker loop).
The explicit `commit()` barrier on top is nearly free (1.06×, +67 rec/s: the
future is already resolved). The synchronous-durable shape costs ~5.7× against
a pipelined producer on this path. Cells to revisit only if a fleet-level
throughput ceiling is ever attributed to Kafka sinks (a pipelined mode with
batched confirmations is the known headroom).
