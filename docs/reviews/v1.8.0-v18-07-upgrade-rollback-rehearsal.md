# v1.8.0 V18-07 drain-first StatefulSet upgrade/rollback rehearsal

Date: 2026-10-08/09. Baseline: `release/v1.8.0` at `54d4a25` (images
`local-20261008181437`, built from the branch). Environment: the `tram-dev`
kind cluster (manager + 3 workers).

## Rehearsal steps and evidence

1. **Upgrade** (chart `existingClaim` path): deployed the branch images via
   `scripts/deploy-kind-tram-dev.sh`, then a values-driven upgrade mounting
   the manually provisioned `tram-worker-journal` PVC through the chart's
   `worker.journal.persistence.existingClaim` — the official upgrade path
   replacing the earlier manual sts patch. The journal data from the
   wave-2 validation survived the re-mount; the RWO claim correctly pinned
   all replicas to the volume's node.
2. **Drain**: triggered a run (310 SFTP files), then POSTed `/agent/drain` to
   the executing worker mid-flight — reply: `{"draining":true,
   "deadline_seconds":30}`; after the deadline all workers reported
   `{"draining":true,"deadline_expired":true,"idle":true,"drained":true}`
   (the safe-to-restart gate). The triggered run completed `success`.
   Operational note: drains issued while a rollout is still replacing pods
   are lost with the replaced pod (drain state is per-process) — drain AFTER
   the fleet is stable, which the runbook now states.
3. **Rollback**: `helm rollback trishul-ram 164` (the last pre-v1.8-code
   release). Verified: the v1.7 fleet rolled healthy, the v1.7 manager runs
   `ok` against the v1.8-era manager DB (extra ledger tables are ignored by
   the v1.7 schema logic), no split-brain, and the journal PVC data was
   untouched (the 1.7 chart has no journal mount).
4. **Roll-forward**: redeployed the branch images + re-applied the
   `existingClaim` values. Verified: drain machinery back (`admitting`),
   journal `ok` with exactly the pre-rollback rows (2 reservations — the
   interrupted and the completed attempt — and 1 completion), manager
   `ok`.

## Bug found and fixed live (`54d4a25`)

The first upgrade attempt at the wave-4 tip **failed**:
`helm upgrade --reuse-values` against a release deployed before
`worker.journal` existed renders with no `worker.journal` at all, and the
worker StatefulSet template crashed dereferencing `.persistence`
(nil pointer). The chart lane's own lint/template verification ran against
the chart's full defaults and missed it — only a real upgrade-from-old
exercises it. Fixed with a nil-safe nested-`with` view so the default
branches (emptyDir, no VCT) apply exactly like `enabled=false`; render
verified with `--set worker.journal=null` plus both persistence combos,
then the live upgrade confirmed green.

## Disposition

The V18-07 deliverable "StatefulSet upgrade/rollback rehearsal" is
**satisfied**: the drain-first runbook (drain → verify drained → rollback →
roll forward) executed end-to-end live, with the journal PVC surviving the
entire round-trip and the compatibility behaviors (v1.8 manager on the
v1.8-era DB under v1.7 code; no journal mount under v1.7) as designed.
