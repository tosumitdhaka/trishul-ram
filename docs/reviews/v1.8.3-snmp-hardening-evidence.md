## H183-04 credential and decode policy

The previous default listener passed `communities=None` and accepted mismatched
communities. The legacy receiver ignored message credentials and emitted corrupt
or encrypted input as normal `_raw` records. Current receivers reject mismatches
and corrupt input with sanitized reasons; valid legacy v1/v2c decode remains
supported. Legacy v3 now fails before binding with an actionable instruction to
use `TRAM_SNMP_STACK=trishul`, because the legacy receiver never authenticated or
decrypted v3 traps. This is a deliberate documented compatibility correction.

`tests/unit/test_snmp_trap_credentials.py` exercises real loopback UDP on both
stacks: wrong community and corrupt input followed by a valid exact Counter64
value of `18446744073709551615`, repeated three times. Default-stack v3 wrong
authentication and privacy keys, plus malformed input, are followed by valid
pysnmp-encoded authPriv traps, also repeated three times. Only the valid records
are emitted; rejection logs contain no keys or complete packets. The pinned
library may include a short BER prefix in its categorized drop warning.

Supported Python 3.13.15 verification with `TRAM_TEST_SNMP_WIRE=1` covered
`test_snmp_connectors.py`, `test_snmp_decode_equivalence.py`,
`test_snmp_tsnmp_paths.py`, `test_snmp_wire_cross_stack.py`,
`test_snmp_trap_credentials.py`, `test_snmp_poll_targets.py` and
`test_api_config_schema.py`: **227 passed**, no skips, one existing Starlette
httpx deprecation warning. A subsequent added deadline regression brought the
focused pilot suite to **20 passed**. Scoped Ruff and the example pipeline's
`tram validate` check passed.

## H183-07 bounded ten-IP pilot

[Reusable live profile](../../scripts/verification/snmp-ten-target-pilot.py)
and [raw evidence](../../scripts/verification/results/v1.8.3-snmp-pilot-2026-10-13.json).
Run the profile with `TRAM_TEST_SFTP_URL` pointing to a disposable SFTP fixture
and `--evidence /path/to/output.json`. It creates its own output subdirectories
and retains categorized JSONL for readback. Do not point it at deployed services.

The synthetic agents used ten distinct loopback IPs `127.0.0.11`–`127.0.0.20`,
SNMP v2c, trishul-snmp 0.6.2, and GET OIDs `1.3.6.1.2.1.1.1.0` and
`1.3.6.1.2.1.1.3.0`. Concurrency was 4; request timeout 0.15 seconds, retries 0,
whole-device timeout 1 second. Classified scalar records used `index_depth: 1`.
The runner used Python 3.13.15 on Linux/WSL2, 12 visible CPUs, with measured
maximum process RSS 292864 KiB (approximately 286 MiB). Agents and runner were
host processes, not resource-limited containers. The separate SFTP fixture
at localhost:12283 used `atmoz/sftp:alpine`, image digest
`sha256:7e439fabeae536fa254340724c042e11999924d906417dbb5c73602ad518813f`,
limited to 1 CPU and 256 MiB. The pipeline used `thread_workers: 1`.

| Scenario | Repetitions | Result |
|---|---:|---|
| Healthy ten-IP cycle | 3 | SUCCESS; 10 exact attributed records per cycle, healthy cycle durations 0.276 / 0.235 / 0.245 seconds |
| Nine healthy plus absent tenth agent | 3 | FAILED with per-target status summary; all 9 healthy records committed and read back, durations 0.239 / 0.237 / 0.263 seconds |
| Stop active polls, then restart with fresh source/agents | 3 | Real unanswered UDP requests cancelled; ABORTED, all 10 targets accounted for, no output; stop durations 0.144 / 0.147 / 0.141 seconds; subsequent healthy cycles succeeded |

SFTP readback checked every device identity, exact sysDescr and sysUpTime values,
record count, and even/odd categorized files. The absent agent can produce a
transport failure (`poll_failed`) rather than a request timeout on loopback;
whole-device timeout isolation is separately pinned deterministically. The
results demonstrate the pilot under these recorded local conditions, not
external fleet/network throughput.

`tests/unit/test_snmp_poll_targets.py` additionally pins admission bounds,
concurrency peak, unchanged single-host payloads, failed rendering isolation,
per-target binding/record counts, actual `counter_delta` runtime metadata and
separate device keys across two poll cycles, and local staged output publication
through the real executor with `thread_workers: 1` and `2`. Stop and deadline
propagation report ABORTED after active poll cleanup. The controller regression
constructs an actual pilot scheduler job with `max_instances=1` and exercises its
running guard to reject replacement execution.

The batch executor explicitly owns terminal source completion after successful
sink drain/commit. Standalone source iteration still raises its terminal error.
Retries may duplicate already-delivered healthy device records under the
existing at-least-once policy. No dependency bump was needed.
